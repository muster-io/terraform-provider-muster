# AGENTS.md

The guide for coding agents, and for humans, who change `terraform-provider-muster`: the Terraform and OpenTofu
provider of Muster, which keeps Muster's configuration as code through its API. Read it before every task.

## Precedence

This file and the documents it points to **override** instructions from directories above this repository and from
global agent configuration about code style, frameworks and architecture. Where they are silent, ask in the pull
request instead of importing conventions from elsewhere.

## Sources of truth

In this order; an earlier source wins over a later one.

1. Muster's capability [C-33](https://github.com/muster-io/muster/blob/master/design/prd/l2/C-33-terraform-provider.md)
   with its `C-33.FR-n` and `C-33.AC-n`, and the ADRs it cites (ADR-0001 for the licences).
2. The story contract in Muster's [`design/stories/`](https://github.com/muster-io/muster/tree/master/design/stories)
   with `repository: muster-io/terraform-provider-muster`. Stories and their issues live in Muster's repository.
3. [`api/openapi.yaml`](api/openapi.yaml), the copy of Muster's specification: **never edited by hand**. Exactly one
   of two files pins it: `api/MUSTER_VERSION`, a Muster release `X.Y.Z` (its tag `vX.Y.Z`), or `api/MUSTER_COMMIT`, a
   commit of Muster's `master` while the release the provider needs does not exist yet. `make spec-sync
   VERSION=x.y.z` pins a release, `make spec-sync COMMIT=<sha>` a commit, `make spec-sync` Muster's current `master`;
   each replaces the copy and runs `make generate`. `make spec-check` fails when the copy differs from its pin. A
   change to the API is made in Muster's repository first.

## Stack

- Go 1.27 (the `go` line of `go.mod`), module `github.com/muster-io/terraform-provider-muster`.
- [terraform-plugin-framework](https://github.com/hashicorp/terraform-plugin-framework) over plugin protocol 6, at
  the address `registry.terraform.io/muster-io/muster`; terraform-plugin-testing for the acceptance tests;
  terraform-plugin-log (`tflog`) for logs.
- The client of Muster's API, generated by oapi-codegen from the copy of the specification into
  `internal/client/gen/` (`make generate`), never edited by hand.
- tfplugindocs generates `docs/` from the schema, `templates/` and `examples/` (`make docs`); GoReleaser builds the
  release; release-please versions it, `0.x`, independent of Muster's versions.

## Layout

| Path | Content |
|---|---|
| `main.go` | serves the provider; `-debug` for a debugger; `main.version` is set by the release build |
| `internal/client/` | the client: base URL `<endpoint>/api/v1`, bearer token, User-Agent, 60 s per attempt, no redirects, the retries with `Retry-After` capped at 60 s (`client.go`), the problems (`problem.go`) |
| `internal/client/gen/` | generated from `api/openapi.yaml`; never edited by hand |
| `internal/provider/` | the provider's configuration (`provider.go`), the version check (`version.go`), the machinery every resource shares (`resourcekit.go`), and the resources and data sources |
| `internal/acctest/` | what the acceptance tests share: the provider factories, the pre-check, a client for changes behind Terraform's back |
| `test/muster-dev.sh` | `up` starts PostgreSQL and `muster dev` from Muster's image and prints the variables of the acceptance tests; `down` removes them |
| `api/` | the specification's copy, its pin and the oapi-codegen configuration |
| `templates/`, `examples/`, `docs/` | the documentation's templates, the examples, and the generated documentation the Registries show |
| `.github/` | the workflows, Renovate and the pull request template |

## Make targets

The Makefile is the only entry point; `make help` lists the targets. `make ci` runs what a pull request runs, except
`vulncheck`, the GoReleaser snapshot and the acceptance tests, which CI runs as jobs of their own. The tools are pinned
in the Makefile under `# renovate:` comments and built into `bin/tools/`.

The acceptance tests need Linux with Docker, jq and Terraform or OpenTofu:

```sh
eval "$(test/muster-dev.sh up)"   # MUSTER_ENDPOINT, MUSTER_TOKEN (Admin) and MUSTER_RESPONDER_TOKEN (Responder)
make testacc                      # ACC_RUN='^TestAccProvider' narrows them
make testacc ACC_RUN='_oldCLI$$' ACC_SKIP=   # the old-CLI tests, with Terraform 1.10 or OpenTofu 1.10
test/muster-dev.sh down
```

`make testacc` runs the tests matching `ACC_RUN` (`^TestAcc`) and not `ACC_SKIP` (`_oldCLI$$`, make's spelling of
`_oldCLI$`); `TESTARGS` is appended to `go test`. Without `MUSTER_ENDPOINT` it starts and stops `muster dev` itself. The image is
`ghcr.io/muster-io/muster:v<api/MUSTER_VERSION>`, or `:sha-<7 hex digits of api/MUSTER_COMMIT>`; `MUSTER_IMAGE`
replaces it. `TF_ACC_TERRAFORM_PATH` chooses the CLI; for `tofu` the tests use the OpenTofu Registry's address.

## Rules

- Every resource uses `resourcekit.go`: the computed `etag` and `If-Match` on every update and delete; a `412`, and a
  shared object whose managed part changed, end in the error of C-33.FR-8 without a retry; an object that several
  resources write is written through `SharedWrite` under its lock; `RequireManagedBy` on every create and update body;
  `ImportByID` and `ParseCompositeID`; `RemoveIfNotFound` on reads; `Object.ErrorDiagnostics` for every error of the
  API; `SecretAttributes`, `SecretToSend` and `ValidateWriteOnly` for every Secret.
- Update and Delete take `If-Match` from the `etag` of `req.State`: the planned `etag` is unknown. Every write stores
  the ETag of its answer in `etag`, the `Write` of a `SharedWrite` included: it keeps the new ETag for the resource
  to store, since the next write of the object sends it.
- A union body (Connections, Destinations) has no `managed_by` of its own: call `RequireManagedBy` on the variant
  struct, then `From<Variant>`. `RequireManagedBy` fails on a body without the field, which `SetManagedBy` only
  reports.
- A test that only Terraform 1.10 and OpenTofu 1.10 run, such as one that asserts that write-only attributes are
  refused, is named `TestAcc…_oldCLI`: `make testacc` skips it, and the job old-cli runs only these tests.
- Attributes follow the API (C-33.FR-7): its field names, `*_seconds`, `public_id` as `id`, references as `*_id`. The
  provider checks types and enumerations only; every bound is the server's.
- The minimum Muster version is `MinimumMusterVersion` in `internal/provider/version.go`. Only a plain release
  `X.Y.Z` is compared; any other version passes with a warning.
- Never log, return or print a token: the client logs every request with `Authorization: [redacted]`.
- Inject time: tests drive the client's waits through its `Sleep` and `Now` and never wait for real time.
- Tests run with the race detector; the coverage gate is 80 % of `internal/`, `internal/client/gen/` excluded.
- Every dependency is permissively licensed or unmodified MPL-2.0 (`make licenses`) and stated in the pull request with
  its licence, latest release date and maintenance status.
- Every Go file, workflow, YAML file, `renovate.json5`, shell script and the Makefile start with
  `SPDX-License-Identifier: MIT` and `Copyright The Muster Authors` in their comment syntax; `make lint` names a file
  without them.
- Comments are few: document exported identifiers, and explain only what the code cannot say.
- Every GitHub Action is pinned by commit SHA, with its version in a comment.
- Never copy code from Muster or another copyleft project: Muster is under the AGPL and this provider under MIT. Read
  Muster for behaviour only; only its specification, under MIT, is copied.

## Working a story

1. Read the story contract in full, and the capability and ADRs it cites. An open question is settled by the
   maintainer before the code that depends on it is written.
2. Stay within `files_touched`. If the contract is wrong or incomplete, correct the story file in Muster's repository
   and say so in the pull request.
3. Give evidence for every `acceptance` statement: a named test, or a command with its output. Unit tests alone never
   prove a story; the live check is `make testacc` against `muster dev`, on Terraform and on OpenTofu, and the manual
   checks of the story's Verification.
4. Run the story's `verify` until it passes.

## Commits and pull requests

- Conventional commits on one line, `<type>(<scope>): <description>`; say what changed, without story or phase IDs.
- No AI attribution: no `Co-Authored-By` trailers, no "Generated with" lines, in commits or pull requests.
- Pull requests are squash-merged; the title is the commit message and release-please's changelog line.
- The pull request body has `Part of muster-io/muster#<issue>` — a pull request here does not close an issue in
  Muster's repository, so the issue there is closed by hand once it merges — `Story: S-NNN`, a table with every
  `acceptance` statement and its evidence, the output of `verify`, every change to the story file with its reason, the
  dependencies added, and the steps the maintainer takes outside the repository.
- Contributions are under MIT, without a CLA.

## Don't

- Edit `api/openapi.yaml`, `api/MUSTER_VERSION`, `api/MUSTER_COMMIT`, `internal/client/gen/` or `docs/` by hand.
- Widen the scope beyond the story: no drive-by refactors or extra features.
- Log, return or print a secret, a token or a URL that carries one.
- Wait for real time in tests.
- Call a story done on unit tests alone, or report a check that was not run.
